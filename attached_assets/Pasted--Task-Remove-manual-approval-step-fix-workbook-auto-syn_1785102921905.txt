## STEP 1 — Database schema: drop "review" / "approved" / "rejected" as separate states

File: `lib/db/src/schema/episodes.ts`

Change the `episodeStatusEnum` from:
```ts
export const episodeStatusEnum = pgEnum("episode_status", [
  "draft", "scripted", "complete", "review", "approved", "scheduled", "published", "building", "rejected",
]);
```
to:
```ts
export const episodeStatusEnum = pgEnum("episode_status", [
  "draft", "scripted", "complete", "scheduled", "published", "building",
]);
```

Rationale: "review" and "approved" were the manual gate; "rejected" was the manual reject
outcome. None of these are needed once approval is automatic. An episode that is content-complete
moves straight to "scheduled" once it has a post date, computed exactly the way the old
`/episodes/:id/approve` endpoint did it (see Step 3).

After editing the schema, run the migration:
```
cd lib/db && pnpm exec drizzle-kit push --force --config ./drizzle.config.ts
```

**Before running this**, write a one-off data-migration script `lib/db/src/migrate-remove-approval-states.ts`
that runs first and remaps any existing rows so nothing gets stuck on a status value that
no longer exists:
- `review` → `complete`
- `approved` → `scheduled` (and if `scheduledPublishAt` is null, compute it from `postDate` + `09:00:00Z`, same formula as the old approve endpoint)
- `rejected` → `draft` (send it back to the top so it gets reworked)

Run this script BEFORE `drizzle-kit push --force`, using raw SQL (since the enum values
still exist in the DB until the push runs):
```sql
UPDATE episodes SET status = 'complete' WHERE status = 'review';
UPDATE episodes SET status = 'scheduled', scheduled_publish_at = COALESCE(scheduled_publish_at, (post_date || 'T09:00:00Z')::timestamptz) WHERE status = 'approved' AND post_date IS NOT NULL AND post_date != '';
UPDATE episodes SET status = 'complete' WHERE status = 'approved';
UPDATE episodes SET status = 'draft' WHERE status = 'rejected';
```

## STEP 3 — API server: auto-schedule instead of manual approve

File: `artifacts/api-server/src/routes/episodes.ts`

1. Remove the `POST /episodes/:id/approve` and `POST /episodes/:id/reject` routes entirely.
2. In the `GET /episodes/:id/build-status` route (or wherever `buildStage` is set to
   `"preview_ready"` / `"exported"` after a successful export), immediately apply the
   same logic the old `/approve` route used to require a manual click for:
   ```ts
   // Auto-schedule: once an episode's build is confirmed exported, move it straight
   // to "scheduled" (no human approval step). scheduledPublishAt is derived from
   // postDate + 09:00 UTC, same formula the old manual approve endpoint used.
   if (videoExists && episode.status !== "scheduled" && episode.status !== "published") {
     let scheduledPublishAt: Date | null = null;
     if (episode.postDate) {
       const d = new Date(`${episode.postDate}T09:00:00Z`);
       if (!Number.isNaN(d.getTime())) scheduledPublishAt = d;
     }
     await db.update(episodesTable).set({
       status: "scheduled",
       approvedAt: new Date(), // keep this column as an "auto-cleared-at" timestamp
       updatedAt: new Date(),
       ...(scheduledPublishAt ? { scheduledPublishAt } : {}),
     }).where(eq(episodesTable.id, episode.id));
   }
   ```
3. Update the `EpisodeStatusValue` type at the top of the file — remove `"review" | "approved" | "rejected"`.
4. Update `GET /episodes/stats` — remove `review`, `approved`, `rejected` from the `byStatus` object.
5. Search the rest of this file for any other reference to `"approved"` / `"review"` / `"rejected"` and remove.

## STEP 6 — Fix seed-episodes.ts (this is the root cause of "files don't update" + "category system wrong")

File: `scripts/src/seed-episodes.ts`

Problems today:
- It has hardcoded logic (`if epNumber >= 51 && epNumber <= 65 → status = "approved"`,
  `if epNumber >= 66 && epNumber <= 100 → status = "scripted"`) that was a one-time hack
  and breaks for any future episode range.
- It only runs when someone manually types the pnpm command — nothing triggers it
  automatically when the workbook file changes.

Fixes:
1. **Delete the hardcoded range overrides** (the two lines starting with
   `// User directive: new batch 51–65...`). Status should come purely from
   `workbookStatusToDb(p.status)` reading the workbook's own "Status" column — that's
   the single source of truth from now on, no hardcoded ep-number special cases.
2. Update `workbookStatusToDb()` to map workbook status text to the new (Step 1) enum:
   ```ts
   function workbookStatusToDb(status: string): DbStatus {
     const s = String(status ?? "").toLowerCase();
     if (s.includes("published")) return "published";
     if (s.includes("scheduled")) return "scheduled";
     if (s.includes("complete") || s.includes("approved") || s.includes("test")) return "complete";
     if (s.includes("scripted")) return "scripted";
     return "draft";
   }
   ```
3. Add a new npm script in the root `package.json`: `"sync-workbook": "pnpm --filter @workspace/scripts exec tsx ./src/seed-episodes.ts"`.
4. **Add a "Sync Workbook" button to the Dashboard** so Nadeem never has to touch a
   terminal:
   - New API route `POST /api/episodes/sync-workbook` in `artifacts/api-server/src/routes/episodes.ts`
     that shells out to run the seed script (`spawn`/`execSync` the same way
     `export-video.ts` already shells out to ffmpeg elsewhere in this repo) and returns
     `{ inserted, updated }` counts.
   - New button on `Dashboard.tsx` near "New Episode": **"Sync Workbook"** — calls this
     route, shows a toast with the inserted/updated counts, then refetches
     `useListEpisodes` / `useGetEpisodeStats` so the page updates immediately without a
     manual page reload.

This directly fixes both "Files update nahi" (one click now re-syncs) and the Category
